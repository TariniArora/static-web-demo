CI/CD Pipeline

What is Continuous Integration?

Continuous Integration (CI) is the practice of automatically building and testing software whenever developers make changes to the source code.

What is Continuous Deployment?

Continuous Deployment (CD) automatically delivers successfully tested changes to the production environment.

Pipeline Flow

The CI/CD workflow used in this project can be represented as:

Code → GitHub Repository → GitHub Actions → Build → Test → Deploy → GitHub Pages

Benefits of CI/CD

  • Automates software testing
  • Detects errors early
  • Reduces manual deployment work
  • Improves software quality
  • Enables faster software delivery

Instructable: GitHub Actions & GitHub Pages

Step 1: Create a GitHub Repository

Create a new repository on GitHub and upload the website files, including the HTML and CSS files.

Step 2: Add the Website Files

Add the required HTML and CSS files to the repository. The HTML file contains the structure and content of the website, while the CSS file controls its appearance.

Step 3: Configure GitHub Actions

Create a GitHub Actions workflow that runs whenever changes are pushed to the repository. The workflow can automatically build and deploy the website.

Step 4: Build and Deploy

GitHub Actions executes the workflow and publishes the website using GitHub Pages.

Step 5: Access the Website

After the workflow completes successfully, the website can be accessed through the GitHub Pages URL associated with the repository.

Conclusion

GitHub Actions makes it possible to automate the CI/CD process, while GitHub Pages provides a simple way to host and publish the website.
